# OctoAcme Project Management Docs

This directory contains OctoAcme’s project management processes, roles, and working guidance. Use this README as an entry point to the process documentation.

## Project management processes

OctoAcme manages work through a lifecycle that begins with initiation—validating the business need, outcomes, stakeholders, and resources—and moves into planning, where approved work is broken into prioritized, shippable backlog items with acceptance criteria, estimates, milestones, dependencies, and a Definition of Done. Execution tracks work on a project board and uses small pull requests with issue links, CI checks, and review before release. Releases progress through staging and smoke tests, production verification, and communication to stakeholders; retrospectives capture lessons and improvement actions.

The Project Manager coordinates delivery, schedules, risks, dependencies, documentation, and communication. The Product Manager defines outcomes, prioritizes work, and measures success. Developers build and test features, collaborate on design and reviews, and surface technical risks; QA/testing validates acceptance criteria and feature quality, while stakeholders provide input and approvals.

Communication keeps progress and decisions visible through standups, weekly delivery and PM–Product Manager syncs, stakeholder updates, milestone demos, and retrospectives. The team maintains a risk register and a project source of truth, and escalates blockers from the team through the PM and Product Lead to the sponsor when needed.

Quality assurance includes unit and integration tests, automated tests and linting in CI, security scanning, end-to-end smoke tests for critical flows, and manual QA when appropriate. Release readiness includes passing checks, a rollback or mitigation plan, staging verification, and post-deployment checks. Teams monitor delivery and product signals, then track retrospective improvements with owners and due dates.
